# web-research-standards — 联网信息质量共享规范

> 适用：所有联网搜索/信息整合类 skill 与 automation。思路源自 last30days-skill（github.com/mvanhorn/last30days-skill）。
> 定位：核心思路，不是操作手册；与具体 skill 既有流程冲突时按 skill 流程执行，本文只在 skill 未覆盖处适用。

## A 先把查询问对（搜索前）

差查询搜不出好结果。开搜前自查：词是否过泛、实体是否同名歧义、数字/型号是否会招来无关内容、"怎么用 X"式措辞是否该改成讨论区说法、非英文主题是否选了真正索引该语言的平台。有问题就花一回合澄清或改写，别硬搜。非交互场景不提问，按最合理解释执行并在产出中标注假设。

## B 社区与社交内容（采集与综合时）

本轮新采的社区或社交 UGC，以对象自身可见的原生正向计数不少于 10 作为最终证据门槛；帖子、回答、视频、评论或回复分别计算。官方资料、论文、正式演讲、榜单和结构化实时数据不适用这个门槛。

通过门槛后，只保留与任务直接相关的具体经验、比较、反驳或观点；需要判断共识时，再看独立来源是否重复出现。

## C 交付时说清覆盖面

用一句话说明内容在说什么、为什么值得看，并附来源、发布时间；社区内容同时附采集时的原生正向计数。说明会影响结论的来源缺口。

## D 取数方式

浏览器慢、占内存、会碰登录态，所以按需升级：公开内容先用 HTTP/fetch 或公开 API；需要交互、登录态、JS 渲染，或 fetch 只拿到空壳页时再开浏览器。遇到登录墙先用本机已有登录态和已存凭据，真缺凭据才问；不绕过人机验证。

## 消费者

公开 skill（domain-explorer、smart-buyer、free-token-eggs）对外自包含，各自内联需要的原则，不引用本文件；内部 skill 与 automation 需要时直接引用本文件。
